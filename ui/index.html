About the data

Where the data comes from

Cars live in a Supabase Postgres database and are never bundled into this frontend. Every table, filter option, count and comparison is the result of a live query, so the interface has no opinion about how many cars exist.

The Car Finder translates a request into SQL and runs it through a read-only Postgres function via Supabase RPC. The generated query is shown with every answer, so a wrong result can be traced to a wrong constraint rather than guessed at. Filter and sort state in the explorer compiles to the same SQL, visible under “Show SQL”.

Units

Imperial and metric are separate columns in the database, not client-side conversions. The unit switch in the header changes which column is read for torque, weight and power-to-weight — in the table, in filters and sliders, and in sorting. Power is always in HP and value always in credits, so those never change. Weight and torque range filters reset when you switch, because their bounds belong to the other unit.
